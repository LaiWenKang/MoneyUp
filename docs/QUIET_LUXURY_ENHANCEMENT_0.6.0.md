# MoneyUp Quiet-Luxury Enhancement — 0.6.0 Candidate

**Document date:** 2026-08-28  
**Working branch:** `codex/quiet-luxury-trust-polish`  
**Audited baseline:** `d231c039bec4005d4013d68734e518b77795b832` (`main`)

This is an incremental enhancement plan and implementation record for the existing native SwiftUI application. It is not authorization for a redesign, rebrand, architecture replacement, or data-model rewrite.

## Source of truth and immutable constraints

The decision hierarchy for this slice is:

1. The latest working implementation, merged pull requests, release gates, and approved repository documentation.
2. The Golden PRD attachment dated 2026-08-26 and the 0.4.0 product audit, where they remain consistent with the current product.
3. The older PRD attachment as historical intent only.

Where an attachment conflicts with a later implemented decision, the current product wins. In particular, older cloud, subscription, and royal-blue/gold concepts do not override the current local-only, free, soft-green and warm-neutral implementation.

The repository audit fixed the candidate baseline at `d231c039bec4005d4013d68734e518b77795b832`, the merged 0.6.0 scalability/privacy gate. Merged pull requests #11–#21 establish the current native architecture and approved feature sequence. Open issue #10 describes an older 0.4.1 release gate and is stale against this baseline; draft pull request #7 proposes a browser/PWA direction that conflicts with the approved native-only product, so neither was treated as implementation authority. The latest green baseline CI is recorded below. The last successful TestFlight evidence predates the baseline, so upgrade/distribution continuity remains a physical release gate rather than an inferred pass.

The following constraints are immutable for this work:

- Preserve the five tabs, in order: **Today, History, center Log, Plan, Assets**.
- Preserve existing navigation meaning, logging workflows, correction paths, and user familiarity.
- Keep the database local-first and encrypted; do not weaken privacy-cover, key-storage, backup, or restore behavior.
- Preserve balanced double-entry accounting and checked decimal arithmetic.
- Keep each currency separate unless an explicit dated conversion rate supports an estimate; always show currency context and never replace an unavailable value with zero.
- Preserve existing data, migrations, bundle identifiers (`com.laiwenkang.MoneyUp` and `com.laiwenkang.MoneyUp.Widget`), backup compatibility, and TestFlight upgrade continuity.
- Preserve English and Simplified Chinese support.
- Reuse the native SwiftUI architecture and existing components before adding new ones.

## Status vocabulary

- **Implemented — verification pending:** the change and relevant tests are present, and the exact remote SHA passed the automated gates recorded below; the applicable physical-device/runtime matrix is still open.
- **Retained:** explicitly reviewed and intentionally unchanged.
- **Deferred:** valuable follow-up work that is outside this focused slice or needs a physical device, production-sized data, or release credentials.
- **Release blocker:** must pass before merge or distribution.

## Intentionally unchanged

- No tab, core feature, or established workflow is removed or relocated.
- No ledger schema, migration, encryption, keychain policy, backup format, bundle identifier, or multi-currency accounting rule is changed.
- No CloudKit, StoreKit, account sign-in, remote analytics, or new network dependency is introduced.
- No app-icon replacement, rebrand, generic financial illustration, floating-coin motif, neon treatment, or broad glassmorphism layer is introduced.
- No unavailable calculation is converted to zero, and no currencies are combined without an explicit dated rate.

No screenshots or measured physical timings are claimed because this workspace has neither Xcode/Simulator nor access to the required devices, biometric/passcode states, TestFlight build, or representative production ledger. Those gates must be appended here before the branch is declared release-ready or merged.
