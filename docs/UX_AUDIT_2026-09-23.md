# Visual-first UX pass — 23 September 2026

Follows [UX_AUDIT_2026-09-22.md](UX_AUDIT_2026-09-22.md). Same first principles:
a person opening a money app wants **what is left**, **what just happened**, and
**what to do next**, each readable in a glance. This pass removes places where
a screen made people read a word, decode a legend, or see the same prompt twice,
and replaces them with a glyph, a verdict, or a single next step. Exact amounts,
currencies, and dates remain text with monospaced digits.

## Method

Every tab was rendered before and after in light/dark, English/Chinese, with a
populated book and an empty book, plus the launch, locked, and recovery roots
(`AppwideRenderEvidenceTests.testRenderEmptyAndLifecycleStates` is new). The
signed app was then driven on the iOS 27 simulator from a fresh install:
onboarding → first-run Today → Log → Saved → History → Plan → Assets.

## Changes

| Area | Before | After | Why |
|---|---|---|---|
| Category glyphs (History, Today pinned, Plan, Saved banner) | Every transaction row showed the same ↗ arrow; category was a 9 pt dot in a hashed colour. | Each category has a recognisable glyph (fork and knife, bus, house, cart…) in its stable tint. Resolution: catalogue preset symbol → keyword in the English or Chinese name → nearest ancestor → neutral tag. The name stays beside it. | A day of rows now scans by shape. The arrow carried no information on a list that is almost all spending. |
| Transaction direction | Income and refunds differed from spending by green alone. | A corner mark (↓ income, ↩ refund) on the glyph and an explicit `+` on the amount. Transfers and investment events keep their movement glyph. | Colour is never the only signal. |
| History row title | With no merchant, the title was the full path (“Everyday essentials › Food and dining”). | The leaf name leads; VoiceOver still hears the full path. | The glyph already places the category. |
| Budget card (Plan) | Ring and bar showed the same fraction; the ring’s centre was a gauge glyph; a “Spending · month marker” legend explained the chart. | The ring states % used. The legend is replaced by a verdict chip: ✓ On pace / 🐇 Ahead of pace / ! Over budget, with the ⓘ on the same line. The bar fill turns amber when ahead of the month marker. | People should not have to decode a chart to learn whether they are on track. |
| Pace bars | Jumped to new lengths. | Animate length changes with the shared state-change curve (off under Reduce Motion). Amounts are never animated. | After a save, the eye sees what the entry did. |
| First run (Today) | A new book showed “Set my first budget” up to three times (hero, pinned board, monthly card) and “Log first” below the fold. | One “Two steps to a clear month” checklist at the top (log a transaction, set a limit) that ticks off steps as they happen and disappears when both are done. “Has a budget” means at least one limit — onboarding seeds categories without limits. | One next step, not three copies of it. |
| History empty / error / loading | Empty state had no action; the error was an ad hoc stack; loading was a bare spinner. | Shared placeholder for all three: illustration + *Log my first transaction*; warning badge + message + Retry; labelled loading. | The same state looks the same on every screen. |
| Plan empty | Today / 7 days / Month switch shown with no limits to pace. “Tap to set a monthly limit” was grey text. | The switch appears once a limit exists; the hint is a tinted ⊕ label. | Controls appear when they do something. |
| Assets | Loans had an orphan ⓘ under the row. | ⓘ on the Loans header (same as Allowances); the row states *No loan plans* or *Active loans* with a count. | The previous pass removed orphan ⓘs elsewhere. |
| Saved banner (Log) | ✓ Saved · amount. | ✓ Saved · amount · category glyph + name (not for transfers or splits). | Says where the money went without scrolling to the category field. |
| Insights | Income / Expense / Net tiles were words; month-end projection opened with a three-line paragraph. | ↙ ↗ = glyphs on the tiles (net turns to ! when negative); the paragraph sits behind the header ⓘ. | Findings start at the top. |
| Unavailable values | “—” and grey text. | “—” with a warning glyph beside the reason. | Reads as a state, not a missing label. |
| Onboarding | Header repeated each step’s headline; step 2 said “Base currency” twice and the value looked fixed; the balance placeholder repeated its label. | Header is “Step n of 4” + progress; currency row is tinted with chevrons like other pickers; balance prompt is `0.00`. | Fewer words, same meaning. |
| Recovery root | Title left-aligned under a centred layout; primary action small. | Centred title; large primary action. | Cohesion with the lock screen. |

## Guardrails kept

- `QuickLogEntryChrome.swift`'s reviewed executable-inventory digest was
  recomputed for the banner change only; no other pinned Quick Log function
  changed.
- Chart marks, palette, and the chart-guard anchors are unchanged. The pace
  chip and bar tint reuse the validated `ChartSeries1/3/5` roles.
- New strings are bilingual (en, zh-Hans); three now-unused keys were removed.

## Verified

- New unit tests: glyph resolution order and short-word false matches,
  pace status thresholds, signed row amounts (including hidden-amount mode).
- Render evidence: all tabs, empty book, lifecycle roots, secondary screens.
- Simulator walkthrough on an ad-hoc-signed debug build from a fresh install.
- All `Scripts/validate_*.py` source validators pass.

## Not changed, with reasons

- **Log category row glyph.** The category picker is inside the reviewed Quick
  Log input boundary (`QuickLogEntryBody.swift` digest). Adding it is a
  reviewer decision; the Saved banner now carries the glyph after the fact.
- **Insights category bars.** Their frame lines anchor the chart-guard
  mutation self-tests; glyphs there need the anchors updated with a reviewer.
- **Physical-device VoiceOver and large-text pass.** Still open, as before.
